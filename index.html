Analisis Matematika & Filter

1. Kendali PID (Proportional-Integral-Derivative)

Sistem kendali PID menghitung nilai output berdasarkan error $e(t)$, yaitu selisih antara Set Point yang diinginkan dan RPM aktual mesin.

\[ u(t) = K_p e(t) + K_i \int_{0}^{t} e(\tau) d\tau + K_d \frac{de(t)}{dt} \]

Berdasarkan input pada Dashboard, perhitungan yang diterapkan adalah:

  • Aksi Proportional ($K_p$ = 2.0): Memberikan respon koreksi yang sebanding dengan besaran error saat ini.
  • Aksi Integral ($K_i$ = 0.1): Menjumlahkan error dari waktu ke waktu untuk menghilangkan steady-state error (kesalahan statis).
  • Aksi Derivative ($K_d$ = 0.1): Memprediksi laju perubahan error untuk meredam lonjakan (overshoot) dan menstabilkan osilasi.
Penyederhanaan Logika PID Terhadap Grafik:
Output PWM $=$ (2.0 $\times$ Error) $+$ (0.1 $\times$ Akumulasi Error) $+$ (0.1 $\times$ Laju Perubahan Error)

  • Ketika grafik RPM jauh di bawah Set Point (Delay & Rise Time): Error sangat besar, sehingga nilai Proportional akan merespon dengan mendorong motor sekencang mungkin ke atas.
  • Ketika grafik tertahan di bawah Set Point (Steady State Error): Nilai Integral akan terus mengakumulasi dorongan perlahan-lahan sampai grafik menyentuh Set Point.
  • Ketika grafik melesat tajam ke atas (Mencegah Overshoot): Nilai Derivative membaca grafik yang naik terlalu cepat, sehingga ia akan "mengerem" dorongan agar grafik tidak kebablasan melebihi garis hijau.

Fenomena Integral Windup & Anti-Windup Kecepatan

Integral Windup: Kondisi ketika motor mengalami saturasi beban atau batas tegangan maksimum PWM, tetapi target RPM belum juga tercapai. Akibatnya, nilai Integral terus menjumlahkan error secara ekstrem (tergulung/windup). Begitu RPM menyentuh Set Point, tumpukan error raksasa tersebut tidak bisa langsung hilang sehingga motor terus berputar kencang, memicu lonjakan (*overshoot*) yang parah dan lama.

Anti-Windup: Metode pengaman yang berfungsi mengunci atau menghentikan akumulasi nilai Integral (*clipping/freezing*) sesaat setelah output kendali mencapai batas saturasi maksimum PWM. Dengan membatasi memori error masa lalu ini, grafik RPM dapat segera melambat and kembali turun secara presisi begitu mendekati target tanpa *overshoot* berlebih.

2. Karakteristik Respon Sistem

Untuk mengukur seberapa baik sistem kendali bekerja, kita menganalisis bentuk grafik yang dihasilkan menggunakan istilah-istilah berikut:

  • Delay Time (Waktu Tunda): Waktu yang dibutuhkan grafik untuk mencapai 50% dari target (Set Point) untuk pertama kalinya sejak mesin dinyalakan.
  • Rise Time (Waktu Naik): Waktu yang dibutuhkan grafik untuk melesat naik dan pertama kali menyentuh atau melintasi garis penuh Set Point.
  • Overshoot (Lonjakan Maksimum): Kondisi ketika grafik kebablasan melesat naik melewati batas garis Set Point sebelum akhirnya turun kembali. Jika nilainya terlalu tinggi, berarti sistem terlalu agresif.
  • Settling Time (Waktu Menetap): Waktu yang dibutuhkan grafik untuk berhenti berosilasi (naik-turun) secara ekstrem dan mulai stabil bertahan di dekat garis Set Point.
  • Steady State (Kondisi Tunak): Fase akhir perjalanan grafik di mana kurva kecepatannya sudah mendatar, stabil, dan tidak lagi menunjukkan perubahan besar seiring berjalannya waktu.
  • Steady State Error (SSE): Jarak atau selisih antara nilai Set Point dengan posisi grafik saat berada di fase Steady State. Sistem yang sempurna memiliki SSE = 0 (grafik menempel persis pada garis Set Point). Jika grafik mentok mendatar di bawah atau di atas Set Point, jarak itulah yang disebut Steady State Error.

3. Filter Digital (Alpha Filter / EMA)

Untuk menghaluskan pembacaan data RPM dari sensor yang fluktuatif/bergetar, digunakan Exponential Moving Average (EMA).

\[ Y_n = \alpha \cdot X_n + (1 - \alpha) \cdot Y_{n-1} \]

Penjelasan Komponen Rumus:

  • $Y_n$ (Output Filter Saat Ini): Hasil akhir RPM yang sudah dihaluskan dan siap ditampilkan di grafik/layar Anda.
  • $X_n$ (Input Mentah): Nilai RPM asli pembacaan sensor pada detik ini yang mungkin masih melompat-lompat (noise).
  • $\alpha$ (Faktor Kepercayaan / Alpha): Persentase seberapa besar kita mengambil data mentah baru. Jika $\alpha = 0.2$, artinya kita hanya mengambil 20% dari data mentah.
  • $(1 - \alpha)$ (Sisa Persentase): Jika $\alpha = 0.2$, maka $(1 - 0.2) = \mathbf{0.8}$. Angka 0.8 ini adalah 80% sisa kepercayaan kita yang dipertahankan dari data lama agar grafik tidak tiba-tiba melonjak drastis.
  • $Y_{n-1}$ (Output Filter Sebelumnya): Nilai RPM halus dari satu hitungan detik sebelumnya yang disimpan di memori mikrokontroler.
Penyederhanaan Logika (Misal $\alpha = 0.2$):

$Y_{filter} = (0.2 \times RPM_{mentah}) + ((1 - 0.2) \times RPM_{sebelumnya})$

4. Evaluasi Kestabilan Akhir

Setelah sistem melewati waktu Settling Time atau saat hitung mundur selesai, sistem mengevaluasi keberhasilan target:

  • Steady State Error (SSE): Terjadi jika grafik RPM merata di bawah target dan tidak pernah menyentuh garis Set Point sama sekali.
  • Stabil (Toleransi 5%): Terjadi jika grafik berhasil menyentuh Set Point, dan pada titik akhir pengujian, nilai RPM mampu bertahan stabil di dalam batas toleransi $\pm 5\%$ dari Set Point.
